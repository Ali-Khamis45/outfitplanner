# Sprint 0 technical debt — 2026-10-31

These are findings, not completed fixes. Priority reflects the work needed to establish the Sprint 0 proof, not a production launch checklist.

## P0 — blocks the proof

1. **SAM model access and environment.** The official checkpoint is pending approval. WSL failed with `HCS/ERROR_NO_SYSTEM_RESOURCES`; the CUDA PyTorch install was interrupted, `nvcc` was not found in the earlier WSL inspection, and Detectron2 plus its official ViTDet weights are not installed/verified. Do not download gated files until access is granted. Verify CUDA PyTorch, detector build, driver/toolkit compatibility and actual VRAM demand without paid services.
2. **No real inference or benchmark.** `reconstruct.py` and metadata fields are prepared but untested against actual SAM outputs. Source and mock tests do not establish valid output, performance, visibility detection or camera behavior. Record actual errors, model and detector hashes, device, dimensions, time and peak memory on real authorized inputs.
3. **No integrated reconstruction workflow.** `ReconstructionPanel.tsx` previews a local file but deliberately disables reconstruction; there is no orchestration, real state transitions, private generated-asset retrieval or reset from a reconstructed result. Do not enable the button until the entire flow is real and safely scoped.
4. **Real MHR mapping and rig deformation unverified.** `sam3d_mhr_adapter.py` assumes source-derived vector lengths, topology equality and a provisional 0.0001 m tolerance. Tests construct expected vertices from the same MHR model, so they test the adapter contract but do not independently establish SAM compatibility. Validate against actual outputs, matched checkpoint assets and independent geometry; verify bind transforms and posed/animated deformation. The official exporter truncates to four influences.
5. **No validated dressing pose.** The adapter preserves estimated pose. Zeroing all 204 values would also change scale and root parameters. Determine a named-parameter-based pose preserving identity and scale; inspect deformation and clothing fit before choosing it.
6. **Browser verification unavailable.** No visual evidence exists for the GLB, orbit/zoom/presets, skeleton and wireframe toggles, screenshot, error handling or responsive layout. Node GLTFLoader and HTTP 200 do not test WebGL or human-visible quality.

## P1 — reproducibility and engineering

7. **Official MHR Python demo/core tests blocked.** The Windows viewer uses TorchScript successfully but `pymomentum` is missing; two upstream core test modules failed collection. Reproduce the official recommended Pixi setup on a functioning supported platform or document a tested alternative. Do not describe the TorchScript viewer test as the full upstream demo.
8. **Dependencies and documentation drift.** The frontend lockfile exists and MHR requirements list pins installed versions, but no complete SAM environment lock or artifact hashes exist. `README.md`, `docs/setup/environment.md`, and `docs/architecture/research-licenses.md` contain stale foundation-era statements (for example that there are no tests or research checkouts). Consolidate versioned, tested setup instructions after the environment is actually runnable; document optional model and transitive license terms.
9. **Validator limitations.** `validate_glb.py` checks selected structural properties but is not full glTF conformance validation, does not prove all bind/node transforms are correct for all inputs, and assumes documented units/up-axis. Add an independent conformance and animated-deformation check. The adapter tolerance requires measurement on real CPU/GPU outputs.
10. **Tests do not cover complete execution.** Failure-path mocks and synthetic tensors do not test the official detector, model download, real inference, end-to-end UI state machine, malformed asset browser handling or three authorized photos. The Node test checks `SkinnedMesh`, attributes and helper geometry but does not render, animate or simulate UI controls. Add tests only when the real implementation and environment exist.
11. **Metadata and failure reporting.** Current reconstruction metadata records device, checkpoint hash, dimensions and allocated peak memory only after successful inference and preview. No real benchmark confirms these fields, total GPU usage, cold start, failed-stage records or cleanup after process interruption. Export sidecars and temporary directories can contain personal data; test retention and interrupted-write behavior.
12. **Performance instrumentation.** Demand-rendered FPS is sampled only while frames run; it is not a reliable idle/continuous benchmark, and rendering statistics are not yet correlated with actual browser frames. No time-to-first-visible-avatar or cold/warm inference measurements exist.

## P1 — privacy and scope

13. **Local-only trust boundary.** The fixed Next.js demo endpoint is unauthenticated and `npm run dev` may bind beyond localhost by default. It currently points to the non-personal demo, but replacing the file or exposing a future personal endpoint could leak data. Design a local, ephemeral, scoped personal-asset path before connecting inference; do not treat Git ignore or obscurity as access control.
14. **Deletion and secrets.** Deletion is manual; no retention policy, crash-recovery deletion or verification across backups/browser downloads is implemented. The audit's token-pattern scan is narrow and did not inspect all historical blob contents or external services. The `torch.jit.load`/upstream checkpoint loaders should only load trusted official artifacts with reviewed provenance.
15. **Input validation limitations.** Resolution, contrast and one-person bounding-box checks are heuristic. They cannot guarantee full body visibility, absence of occlusion, camera calibration, correct identity or physical accuracy. Validate behavior with permissioned diverse examples; communicate uncertainty without representing the mesh as an exact body or measurements.
